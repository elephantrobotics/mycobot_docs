# 7.5 性能、日志与故障排查

## 1. 性能参考

当前测试环境下，单次同步通信的平均响应时间约为 `25 ms`。该数据用于同类环境中的性能参考，不是每次调用都必须达到的硬性指标，也不代表机械臂完成运动所需的时间。

测量时应关闭客户端 `debug`，并记录：

- 测试入口（板端 Bridge 或 TCP）
- 调用次数
- 平均、最小和最大耗时
- 失败次数

不要把不同控制入口的结果混合统计。

## 2. 日志与错误帧

排查时可以临时启用 `debug=True`，并收集 App Lab Console 或服务日志：

```bash
journalctl -u mycobot-server.service -n 100 --no-pager
```

Bridge 中以下返回值表示通信异常，不是有效机械臂数据：

| 返回帧 | 含义 |
| --- | --- |
| `FE FE 03 5B 01 FA` | 通信超时 |
| `FE FE 03 5B 02 FA` | 收到残包 |

发生问题时，请保留完整收发日志、发生时间、使用入口和复现步骤。

## 3. 故障排查

| 现象 | 优先检查 | 处理建议 |
| --- | --- | --- |
| `ModuleNotFoundError: pymycobot` | 当前运行环境是板端系统、App Lab 还是 PC | 板端核对预装包；App Lab 检查本地 wheel 和 `requirements.txt`；PC 核对客户端环境 |
| `method XferBridgeMsg not available` | 完整 App 结构和 Sketch 部署日志 | 重新导入完整 ZIP，查看 Start-up 与 Sketch 日志 |
| 版本或角度读取超时 | 机械臂供电、D0/D1 接线、其他控制程序 | 停止其他入口后重新执行只读测试并保存日志 |
| App Lab 无法识别 UNO Q | USB-C 线、板卡启动状态、系统授权 | 更换支持数据的线缆，等待板卡启动后重新选择设备 |
| App 启动但机械臂无动作 | Main/Python 日志、Sketch 日志和项目结构 | 先运行 RGB，再检查 Bridge 方法和接线 |
| TCP 连接被拒绝或超时 | UNO Q IP、同网段、服务状态和端口监听 | 使用实际 IP，检查 `systemctl`、`ss` 和 `journalctl` |
| 第二个 TCP 客户端无响应 | 前一客户端仍占用连接 | 正常关闭旧客户端后再连接，不并发控制 |
| SBC 下手柄不识别 | Hub 供电、驱动、输入设备和项目依赖 | 先运行映射测试；内核不匹配时获取对应驱动 |
| 夹爪或吸泵无动作 | 外设型号、线缆、IO 和案例命令 | 核对外设安装与接线，不在未知配置下重复触发 |

## 4. 提交问题时建议提供

- 设备型号和问题发生时间
- 接线照片及使用的控制入口
- UNO Q 内核、App Lab 和 `pymycobot` 版本
- 完整复现步骤、期望结果和实际结果
- App Lab Console 或 `journalctl` 日志
- 在安全条件下拍摄的运动异常视频

分享日志和截图前，请移除密码、网络凭据及其他敏感信息。
