# 7.5 Performance, Logs and Troubleshooting

The response time of the UNO Q Bridge path is affected by system load, Python code, App Lab state, network quality, and robot firmware response. A value around 25 ms can be used only as a reference, not as a guaranteed real-time value.

## Bridge Error Frames

| Frame | Meaning | Suggested check |
| --- | --- | --- |
| `FE FE 03 5B 01 FA` | Timeout | Check robot power, firmware, Bridge service, and whether another program is occupying control. |
| `FE FE 03 5B 02 FA` | Partial frame | Check communication stability and retry after stopping other control programs. |

When `debug=True` is enabled, the Python log may show `_bridge_error` with the raw frame. This helps locate firmware or communication problems.

## App Lab Issues

| Symptom | Possible cause | Action |
| --- | --- | --- |
| ZIP import fails | The project package is incomplete | Import the complete ZIP instead of copying only `main.py`. |
| UNO Q is not detected | USB-C cable only supports charging | Replace it with a data cable and reconnect. |
| Dependency installation fails | Wheel files are missing or incompatible | Check the project `python/` and wheel files. |
| Run starts but no robot response | Bridge method is unavailable | Check firmware and `XferBridgeMsg` support. |

## Python Issues

| Symptom | Possible cause | Action |
| --- | --- | --- |
| `arduino.app_utils` not found | Running UNO Q Bridge code on a normal PC | Use this mode only on UNO Q Debian / App Lab. |
| `get_angles()` returns no data | Robot is not powered or Bridge timed out | Check power, firmware, and control occupancy. |
| Robot moves unexpectedly | Multiple control entries are active | Stop App Lab, terminal scripts, and TCP clients, then restart one program. |

## TCP Socket Issues

| Symptom | Possible cause | Action |
| --- | --- | --- |
| Connection refused | Socket service is not running | Start or restart the UNO Q socket service. |
| Connection timeout | PC and UNO Q are not on the same LAN | Check IP address, Wi-Fi/Ethernet, and firewall. |
| Movement command fails | Read-only verification was skipped | Test `get_angles()` first, then run low-speed motion. |

## Gamepad Issues

| Symptom | Possible cause | Action |
| --- | --- | --- |
| No controller detected | Receiver not connected or not powered | Use a powered USB Hub and reconnect the receiver. |
| Axis direction is wrong | Controller mapping differs | Run the mapping test and adjust the script mapping. |
| Robot loses holding force | L2 released servos | Focus servos again only after the robot is in a safe posture. |
