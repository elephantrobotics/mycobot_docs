# 7.2.1 Environment and Communication Check

Before running motion examples, verify Python, `pymycobot`, and robot communication.

## Check Python

Open a terminal on UNO Q Debian or the App Lab Python console and run:

```bash
python3 --version
```

## Check pip and pymycobot

Some new UNO Q boards may not have `pip` installed by default. Check `pip` first:

```bash
python3 -m pip --version
```

If the terminal reports `No module named pip`, install it first:

```bash
sudo apt update
sudo apt install -y python3-pip
python3 -m pip --version
```

Then check `pymycobot`:

```bash
python3 -m pip show pymycobot
```

If `pymycobot` is missing in a customer environment, install the project-provided wheel or the required package version according to the release package instructions.

## Read Robot Information

```python
from pymycobot import MyCobot280

mc = MyCobot280(unoq_bridge=True, debug=True)
print("system:", mc.get_system_version())
print("angles:", mc.get_angles())
```

Expected result:

- `get_system_version()` returns a firmware version or a valid response.
- `get_angles()` returns six joint angles.
- No `_bridge_error` is printed.

If a timeout frame such as `FE FE 03 5B 01 FA` appears, check the UNO Q firmware, robot power, and Bridge service state.
