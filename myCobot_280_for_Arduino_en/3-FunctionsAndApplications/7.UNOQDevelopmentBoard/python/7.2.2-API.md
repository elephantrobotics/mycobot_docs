# 7.2.2 API Usage

The UNO Q Python examples use the same high-level `pymycobot` API as the normal myCobot 280 Python workflow. The key difference is the initialization method.

## UNO Q Initialization

```python
from pymycobot import MyCobot280

mc = MyCobot280(unoq_bridge=True)
```

Notes:

- `unoq_bridge=True` enables UNO Q Bridge communication.
- A serial port such as `COM3` or `/dev/ttyUSB0` is not required in this mode.
- The firmware must provide `XferBridgeMsg`.
- Run only one control script at a time.

## Common APIs

| Function | Purpose |
| --- | --- |
| `get_system_version()` | Read firmware version. |
| `get_angles()` | Read current joint angles. |
| `send_angle(id, degree, speed)` | Move one joint. |
| `send_angles(angles, speed)` | Move all joints. |
| `get_coords()` | Read current coordinates. |
| `send_coords(coords, speed, mode)` | Move to coordinates. |
| `set_color(r, g, b)` | Set Atom RGB color. |
| `set_gripper_state(flag, speed)` | Open or close the gripper. |
| `set_basic_output(pin_no, pin_signal)` | Set base IO output. |

For the full API reference, see [6.2.2 API description](../../6.developmentGuide/python/2_API.md).
